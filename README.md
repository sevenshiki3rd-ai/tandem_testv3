# TANDEM v3 — 二者・複数人の相互承認アプリ

**iPhone/Androidでホーム画面に追加できるPWA。** GitHub Pagesで静的ファイルを公開し、Supabaseに接続すると端末間で共有できます。App Store/Play Storeのネイティブアプリ（IPA/APK）ではありません。

## 機能

- 二者モード（2人まで）と複数人モード（12人まで）。1アカウントが20グループまで参加可能
- **タスクはユーザーに1つだけ紐づく**：すべての参加グループに同じタスク・報告・達成状況が表示。グループ別コピーなし
- グループは3つまで固定。それ以外は最新の報告・コメントなどの活動順
- デイリー（週1〜7回）とアクティブなエクストラ（同時に1件）
- スクラッチで報告フォームを開く。写真は任意、コメント添付可能。Android等の対応ブラウザで振動。報告、スタンプ、ご褒美、称賛時に視覚/音の演出
- タスクごとに承認者を指定。N人のうちM人が承認した時点で1スタンプ（自己承認不可）
- 「やれ！」「今やれ！」「そういう日もある」「サボるな！」＋自由文で未報告への発破、承認済み報告には「よくやった！」「えらい！」「進め」など称賛＋自由文
- 誰から誰に、どのグループで、どのタスクに送ったかを記録
- 達成数、過去4週の目標達成率、活動開始からの日数、承認待ち、届いた発破数・称賛数を表示。**グラフなし**
- **先週の実績**（月曜〜日曜）が40%未満なら、翌週本人に理由を確認。「本当にサボってました」を選んだときのみWORST。他の理由は吹き出し。健康・精神面の理由は公開を本人が選択

### 成功率・週次の定義

- **達成扱い**：指定人数から承認済みとなった報告だけをカウント（申告しただけの報告はまだ完了にしない）。
- **先週の達成率**：先週月曜日までに作成済みの有効なデイリータスクに対し、週目標の合計を分母、承認済み報告数を分子とする。例：ジム週3＋読書週7→目標10。承認済み3件なら30%。週途中で作ったタスクはその週の週次判定に入れない。
- **過去4週の成功率**：完了した4週間の分母と分子の合計から計算。タスク設定の変更は過去週まで遡って按分しない簡易計算。
- **活動開始からの日数**：最初のタスク作成日からの経過日数。連続して毎日完了した日数とは区別。
- **WORST**：40%未満のみでは自動付与しない。本人が「本当にサボってました」を選んだ場合に付与。他の理由では公開が有効な場合だけ選択理由をグループ内で表示。
- 時刻・週の区切り：日本時間 `Asia/Tokyo`、月曜開始。

## GitHub Pages公開（デモ）

1. GitHubでリポジトリを作る（例：`tandem`）。ZIPを展開し、**フォルダ内のすべてのファイルをリポジトリの最上位へ**アップロード。
2. GitHubの **Settings → Pages → Deploy from a branch → main / (root) → Save**。
3. URL（通常 `https://ユーザー名.github.io/tandem/`）を開く。`config.js`が空欄なら1台のローカルデモとして起動します。
4. デモは設定画面で A/B/C/D のユーザーを切替可能。Aのタスクがペアと複数人グループに表示される例を含みます。デモのデータは端末のブラウザ内にのみ保存され、他端末とは同期されません。

## 本当にiPhone/Android間で同期する（本番）

1. [Supabase](https://supabase.com/) に**新しい**プロジェクトを作る。**v1/v2とデータ構造が違うため、以前のSupabase DBには適用しない**でください。
2. SQL Editorで `supabase.sql` 全文を実行。
3. Authentication → Providersで **Anonymous Sign-Ins** を有効にする。
4. Project URL と **Publishable key（または従来の anon key）** を `config.js` に書く。**secret / service_role キー、DBパスワードは絶対に書かないこと**。
5. `config.js` をGitHubへ再アップロードして待ち、Safari/Chromeから公開URLを開く。
6. 両端末で別々にゲスト開始→表示名登録。作成者がグループを作り、招待コードを相手に渡す（片方は「招待コードで参加」）。
7. 2人以上になったらタスクを作り、承認担当者と必要承認人数を選ぶ。

### ホーム画面に追加する

- iPhone: Safariで公開URL→共有→「ホーム画面に追加」→「Webアプリとして開く」→追加
- Android: Chromeで公開URL→メニュー→「アプリをインストール」か「ホーム画面に追加」

## 実装上の注意 / 残課題

- **本番の端末間認証・同期はSupabase実機環境で未テスト**。デモ検証と本番接続は別です。
- v3はv2と非互換。データ移行は未対応。
- 匿名ログインは端末に依存します。端末変更・データ削除時に復旧できないため、長期運用する前にメールまたはパスキー等のログイン連携を推奨。
- 写真は非公開バケットに保存され、共通グループメンバーだけが署名付きURLで見る構成。写真は個人情報を含む可能性があるため、共有範囲を確認してください。
- 発破は同一送信者から同一グループ・同一タスクに1日1回、称賛は同一送信者から同一報告に1回まで（スパム抑制）。通知はアプリ画面で確認。**OSのプッシュ通知は未実装**。
- iPhone Safari / PWAのWeb Vibration APIは非対応。スクラッチの視覚効果・SEは利用できます。iPhoneで確実な振動にはCapacitor等でネイティブアプリ化が必要。
- スクラッチ表面は再表示で復元。アクセシビリティ用に「スクラッチできない場合はこちら」も用意。
- ご褒美の交換は累計スタンプ数が必要数に達したら何個でも交換できる累積型（スタンプを消費しない）。
- リアルタイムPush、退会/削除、プロフィール復旧、ミュート、管理者制御、RLSやストレージの本番監査、履歴の巨大化対策は別途実装が必要。
- 現在のSQLは新規Supabaseプロジェクト用。利用前にSQL Editorで実行し、実機・複数アカウントで動作と権限を確認してください。
